# Editorial feedback log

Append one JSON object per line to `events.jsonl`; never rewrite or delete prior events. A short correction is more useful than inventing a new permanent style rule.

Record when the owner explicitly suggests a topic, edits/refuses a draft, asks for a different image, says a post is unusually interesting, or supplies performance information. Include `content_id` when known and the relevant before/after wording or asset. If there is no post ID yet, use `null`.

Keep three things separate: the owner's exact signal, the editor's provisional hypothesis, and later evidence. Direct instructions apply at the stated scope. Do not turn one edit or one high/low reach observation into a universal rule. Promote a repeat pattern only after comparable cases or owner confirmation. Keep observations about performance tied to platform, topic, format, timing, actual publication status and data source.

Required fields are defined in `schema.json`. Values unknown at the time stay `null`; no fabricated metrics or inferred reactions. `content/editorial/feedback/2026-11-04-initial-brief.json` records this redesign brief as the initial direction for the pilot.
